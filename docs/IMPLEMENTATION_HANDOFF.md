# 유튜브 건강검진 — 구현 Handoff

- 기준일: 2026-09-04
- 상태: 제품 범위, 분석 루브릭, 기술 경계 확정
- 대상 도메인: YouTube 건강정보 콘텐츠
- 사용자 입력: 인증한 사용자의 YouTube 구독 목록
- 역할: 다음 세션이 추가 제품 기획 없이 Spec Kit 명세와 구현을 시작하기 위한 최상위 기준

> 이 문서와 다른 문서가 충돌하면 이 문서를 우선한다. 기존 `openai-workshop` 데모 구현은
> 참고하거나 재사용하지 않는다.

## 1. 제품 정의

사용자의 YouTube 구독 채널을 분석해 `콘텐츠 리스크`와 `공장형 가능성`을 이유와 함께 보여주고,
사용자가 직접 선택한 채널만 최종 확인 후 일괄 구독 해제하는 웹앱이다.

두 점수는 모두 위험성이 클수록 숫자가 커지는 0~100점이다. 서로 의미가 다르므로 합치지 않는다.
`허위`, `불법`, `사기`, `AI 생성`을 확정하는 제품이 아니다.

## 2. 잠긴 사용자 흐름

```text
Google 계정으로 YouTube OAuth 연결
→ subscriptions.list로 구독 목록 전체 수집
→ channels.list로 채널 정보와 uploads 재생목록 ID 수집
→ 업로드 재생목록에서 공장형 분석용 메타데이터 표본 수집
→ 채널명·설명과 영상 제목·설명으로 건강 관련 채널 후보 선별
→ 건강 후보마다 최신 영상 2개와 조회 수 기준 인기 영상 3개 선택
→ videoId로 중복 제거
→ videos.list로 영상 메타데이터와 containsSyntheticMedia 보강
→ 규칙 엔진으로 채널별 공장형 가능성 계산
→ LLM judge가 영상별 콘텐츠 리스크를 직접 평가
→ 성공한 건강 영상 결과를 채널 단위로 집계
→ 두 점수, 이유, 표본과 한계를 채널 목록에 표시
→ 사용자가 구독 해제할 채널을 직접 선택
→ 선택한 채널명과 개수를 확인 모달에 표시
→ 사용자 최종 승인
→ 선택한 subscriptionId만 subscriptions.delete로 구독 해제
→ 채널별 성공·실패 결과와 실패 항목 재시도 제공
```

## 3. 데이터와 표본

- `subscriptions.list(mine=true, part=id,snippet)`: `subscriptionId`, 구독 시각, `channelId`,
  채널명·설명·썸네일을 가져오며 `nextPageToken`이 끝날 때까지 순회한다.
- `channels.list(part=snippet,statistics,contentDetails)`: 최대 50개 채널 ID를 묶어 채널 개설일,
  공개 영상 수, uploads 재생목록 ID, 화면용 구독자·조회 수를 가져온다.
- 공장형 수집: 최근 90일 공개 업로드를 순회하고, 반복도 입력은 최근 30일 영상과 최신 20개의
  합집합 중 최신 50개로 제한한다.
- 콘텐츠 리스크 표본: 최신 공개 영상 2개와
  `search.list(channelId, type=video, order=viewCount, maxResults=3)`의 인기 영상 3개다.
- 표본을 `videoId`로 중복 제거한다. 평가에 성공한 건강 영상이 3개 미만이면 채널 리스크는
  `표본 부족`이다.
- `videos.list(part=snippet,contentDetails,statistics,status)`로 제목, 설명, 태그, 게시 시각,
  길이, 조회 수와 `status.containsSyntheticMedia`를 보강한다.
- `containsSyntheticMedia` 필드 부재는 `unknown`이다. `true`는 공개 표시이지 허위 판정이 아니다.

## 4. 공장형 가능성 v1

판정 주체는 순수 규칙 엔진이고 판정 단위는 채널이다.

| 항목 | 최대 감점 |
|---|---:|
| 업로드 간격 및 집중 업로드 | 40 |
| 제목·설명 템플릿 반복도 | 40 |
| 합성 콘텐츠 표시 비율 | 20 |

```text
생산 건전성 점수 = 100 - 공장형 감점
공장형 가능성 = 공장형 감점
```

정확한 v1 계산식, 미측정 조건과 정규화 규칙은 `ANALYSIS_WORKFLOW.md`를 따른다. 구독자 수,
조회 수, 채널 개설 연도 자체는 점수에 넣지 않는다. 모든 상수는 `factory-policy-v1` 한곳에서
버전 관리한다.

## 5. 콘텐츠 리스크 v1

판정 주체는 공개 YouTube URL을 직접 처리하는 단일 LLM judge이고 판정 단위는 영상이다.

| 항목 | 최대 감점 |
|---|---:|
| 행동 유도 여부 | 40 |
| 구매 유도 여부 | 30 |
| 건강정보 출처 명확 여부 | 30 |

```text
영상 안전 점수 = 100 - 콘텐츠 리스크 감점
영상 리스크 = 콘텐츠 리스크 감점
```

LLM은 영상·제공 메타데이터에서 확인한 정보로 세 항목을 직접 채점한다. 별도 주장 추출 LLM,
다른 LLM을 이용한 의미 검증, 외부 검색은 두지 않는다. 코드는 JSON schema, 허용 범위, 항목 합계,
안전 점수 산식과 감점 이유 존재만 검증한다. 같은 근거를 여러 항목에 중복 감점하지 않는다.

직접 영상 입력은 Gemini 공개 YouTube URL 어댑터를 사용한다. OpenAI Responses API는 현재 공식
입력이 텍스트·이미지·파일이고 영상 입력을 지원하지 않으므로 v1 영상 judge 경로에 사용하지 않는다.
비공식 자막, 스크래핑, `yt-dlp`, 영상·음성 다운로드도 사용하지 않는다.

## 6. 채널 집계와 등급

평가에 성공한 고유 건강 영상이 3개 이상일 때만 계산한다.

```text
채널 리스크 = 최고 영상 리스크 × 0.6 + 평가 영상 리스크 평균 × 0.4
```

소수점 첫째 자리에서 반올림해 정수로 표시한다.

| 점수 | 콘텐츠 리스크 등급 |
|---:|---|
| 70~100 | 위험도 높음 |
| 40~69 | 확인 필요 |
| 0~39 | 뚜렷한 위험 신호 없음 |
| 계산 불가 | 표본 부족 |

공장형 가능성도 화면 일관성을 위해 같은 구간명(`높음`, `확인 필요`, `뚜렷한 신호 없음`,
`미측정`)을 쓰되 콘텐츠 등급과 결합하지 않는다. 채널 이유는 감점이 큰 영상부터 의미가 겹치는
내용을 제거해 최대 3개를 표시하고 영상 제목, 근거 문구, 가능한 경우 타임스탬프를 연결한다.

## 7. LLM 출력과 실패 계약

`VideoRiskJudgement`는 `videoId`, `isHealthRelated`, 세 `RiskDeduction`, `totalRiskScore`,
`safetyScore`, 최대 3개 `summaryReasons`, `limitations`, `model`, `promptVersion`, `judgedAt`을
포함한다. `RiskDeduction`은 점수, 이유, 선택적 근거와 시작 시각을 포함한다.

- 공개 영상 처리 실패 시 메타데이터만으로 점수를 만들지 않는다.
- 네트워크·429·5xx는 지수 백오프로 최대 2회 재시도한다.
- 구조·산식 오류는 동일 입력으로 1회만 재시도하고 다시 실패하면 `schema_invalid`로 종료한다.
- 차단, 비공개, 지역·연령 제한, 공급자 오류, 시간 초과를 서로 다른 실패 코드로 보존한다.
- 실패 영상은 0점이 아니며 평균과 최고값에서 제외한다.
- 결과에는 모델, 프롬프트, 스키마와 정책 버전을 저장한다.

## 8. 액션 불변조건

1. 모든 체크박스는 기본 미선택이다.
2. 점수나 등급으로 채널을 자동 선택하지 않는다.
3. 분석 단계는 YouTube 쓰기 API를 호출할 수 없다.
4. 확인 모달은 서버가 현재 세션의 선택 목록으로 다시 만든다.
5. 최종 승인 요청에는 일회성 confirmation ID를 사용하고 선택 목록 해시와 사용자를 검증한다.
6. 각 `subscriptions.delete`는 독립 실행하며 성공과 실패를 섞어 숨기지 않는다.
7. 재시도는 실패한 `subscriptionId`만 대상으로 새 확인을 받는다.

## 9. 범위 밖

- Google Data Portability API, Google Takeout, 최근 시청 기록
- 좋아요·싫어요, `videos.rate`, 홈의 `관심 없음`·`채널 추천 안 함`
- 브라우저 자동화와 YouTube 화면 조작
- 고위험 채널 자동 선택 또는 자동 구독 해제
- 별도 LLM 추출·검증 파이프라인
- AI 공개 표시를 콘텐츠 위험으로 자동 해석하는 로직
- 기존 데모 코드 재사용

## 10. 구현·배포 게이트

- 런타임: Next.js App Router, React, TypeScript, 단일 Node.js 서버, SQLite.
- 검증: 규칙 단위 테스트, API 어댑터 통합 테스트, judge eval, 선택·확인·해제 E2E.
- OAuth 토큰과 API 키는 서버에만 두고 사용자 식별자·구독 ID는 LLM에 보내지 않는다.
- 분석 결과와 API 데이터는 기본 24시간 후 삭제하고, 사용자는 즉시 삭제·연결 해제를 실행할 수 있다.
- YouTube API 데이터로 공장형 점수 같은 파생 지표를 만드는 공개 서비스는 YouTube의 감사와
  명시적 허용이 필요할 수 있다. 승인 전 실행 범위는 개발·테스트 계정용 프로토타입으로 제한한다.

## 11. Spec Kit 시작 순서

`docs/specs/README.md`의 기능 경계를 따라 OAuth·수집부터 순차 진행한다. 첫 명세는 다음처럼 시작한다.

```text
$speckit-specify YouTube OAuth와 구독 전체 수집 기능. PRD의 FR-AUTH-*와 FR-COLLECT-*를 구현한다.
```
