# 시니어 알고리즘 클리너 — 제품 요구사항·판정 기준

- 기준일: 2026-09-04
- 범위: 건강 YouTube 콘텐츠
- 목적: 워크숍 데모의 제품 흐름, 판정 루브릭, 액션 정책을 하나의 기준으로 고정한다.

> **중요:** 이 디렉터리는 기존 임시 데모의 소스 코드를 복사하지 않은 신규 구현 공간이다. 정치 도메인, 단순 정규식 점수, LLM 직접 채점, 최신 영상 5개 분석 등 기존 데모의 가정과 구현을 참조하거나 재사용하지 않는다. 제품과 판정은 이 문서, 구현 흐름은 `ANALYSIS_WORKFLOW.md`, API 데이터 계약은 `API_DATA_DETAILS.md`를 기준으로 새로 구현한다.

## 1. 제품 정의

시니어와 가족이 YouTube의 건강 관련 구독 채널과 실제 최근 시청 영상을 분석하고, 위험한 건강 주장과 공장형 생산 패턴을 근거로 계정을 정리하는 웹 데모다.

분석 결과를 `허위`, `불법`, `AI 생성`으로 확정하지 않는다. 관측 가능한 원문과 공개 지표를 이용해 `우선 정리`, `확인 필요`, `뚜렷한 신호 없음`, `근거 부족`으로 분류한다.

## 2. 판정 원칙

판정에는 다음 두 축만 사용한다.

| 축 | 질문 | 역할 |
|---|---|---|
| 콘텐츠 위험도 | 잘못된 건강 행동을 유발할 수 있는 주장을 하는가? | 핵심 판정 기준 |
| 공장형 채널 가능성 | 유사한 저품질 건강 콘텐츠를 반복·대량 생산하는가? | 채널 패턴을 보여주는 보조 기준 |

시청 횟수와 최근성 등 노출도는 위험 점수에 넣지 않는다. AI 생성 여부도 판정 기준으로 사용하지 않는다. 공장형 점수만으로 액션을 실행하지 않으며, 내용 기반 위험 신호가 반드시 있어야 한다.

## 3. 공통 분석 파이프라인

```text
구독 목록 또는 최근 시청 기록에서 채널·영상 발견
→ YouTube API로 채널 공개정보와 업로드 목록 보강
→ 결정적 규칙으로 대표 영상 선택
→ Gemini가 공개 YouTube 영상의 발언·화면 문구·타임스탬프 수집
→ Gemini 근거 문서를 저장하고 이후 단계에서 재사용
→ OpenAI가 저장된 근거와 메타데이터에서 건강 주장을 구조화
→ 검증기가 구조화 결과와 동일한 Gemini 근거·메타데이터 원문을 대조
→ 콘텐츠 위험도 계산
→ 채널 생산 패턴 계산
→ 두 축을 조합해 등급 결정
→ 고위험 항목 기본 선택 / 중간 위험 항목 사용자 선택
→ 근거 확인과 최종 승인
→ 승인된 API 실행 결과 표시
```

건강 관련성은 점수가 아니라 분석 진입 조건이다. 식품, 약·성분, 의료기기, 운동·생활요법, 검사·시술 등을 질병 예방·진단·치료, 증상 개선 또는 생체지표 변화와 연결하는 콘텐츠만 통과시킨다.

구체적인 두 입력 경로, LLM 간 책임, 저장·재사용과 실패 정책은 [확정 분석 워크플로우](./ANALYSIS_WORKFLOW.md)를 따른다.

### 4.1 고정 점수 규칙

| ID | 신호 | 점수 |
|---|---|---:|
| `H-REPLACE` | 처방약·진료·검사·치료의 중단 또는 대체 권고 | 40 |
| `H-TREAT` | 특정 질환의 예방·치료·완치 효능 주장 | 25 |
| `H-DANGER` | 위험할 수 있는 물질·용량·시술·민간요법 권고 | 25 |
| `H-FOOD-AS-DRUG` | 식품·건강기능식품을 의약품처럼 제시 | 20 |
| `H-GUARANTEE` | 효과를 절대적으로 보장 | 15 |
| `H-UNIVERSAL` | 연령·질환·복용약 차이를 무시한 보편 처방 | 10 |
| `H-SALE` | 치료 주장과 구매·상담·공동구매 유도의 결합 | 15 |
| `H-CONSPIRACY` | 의료인·정부·제약사의 은폐를 전제로 한 주장 | 10 |
| `H-AUTHORITY` | 확인할 수 없는 전문가·기관 권위 표방 | 7 |
| `H-URGENCY` | 공포를 이용한 즉시 행동 유도 | 7 |
| `H-SOURCE` | 연구·기관을 식별할 수 없는 근거 표방 | 7 |
| `H-TESTIMONIAL` | 개인 경험을 일반적 치료 근거로 확대 | 7 |

같은 원문 구간에서 겹치는 규칙은 가장 높은 점수 하나만 반영한다. 독립된 원문 구간은 합산하되 100점으로 제한한다. 원문에 실제로 존재하지 않는 LLM 추출 결과는 폐기한다.

의료행동 위해성은 `H-REPLACE`·`H-TREAT`·`H-DANGER`·`H-FOOD-AS-DRUG` 합계 40점, 주장 강도는 `H-GUARANTEE`·`H-UNIVERSAL` 합계 20점, 근거 투명성은 `H-AUTHORITY`·`H-SOURCE`·`H-TESTIMONIAL` 합계 15점, 기만적 설득·상업성은 `H-SALE`·`H-CONSPIRACY`·`H-URGENCY` 합계 25점으로 각각 제한한다.

각 규칙이 읽는 구조화 필드는 고정한다.

- 건강 주장: 치료 결과, 권고 행동, 확실성, 보편 적용 여부, 대상 유형과 맥락
- 위해 후보: 물질·용량·시술·상호작용의 원문과 방법
- 판매 신호: 구매 링크, 연락처, 공동구매, 협찬, 제품 판매, 상담
- 설득 신호: 음모론, 공포, 긴급성, 체험담
- 출처·권위 신호: 연구·기관·전문가 이름과 식별자 또는 URL

`H-DANGER`는 LLM이 위해 후보를 추출했다는 이유만으로 적용하지 않는다. 사람이 검토하고 버전 관리하는 위험 행동 카탈로그에 대상과 방법이 일치할 때만 적용한다. 카탈로그에 없는 후보는 점수 없이 `확인 필요`로 표시한다. `H-AUTHORITY`와 `H-SOURCE`도 각각 권위 또는 연구를 표방하는 원문이 있으면서 이름·자격·기관·식별자·URL이 비어 있을 때만 적용한다.

다음은 합계와 관계없이 `우선 정리` 후보가 되는 하드 플래그다.

- 기존 치료·처방약 중단을 직접 권고
- 중증 질환 완치 주장과 제품 판매가 결합
- 즉각적인 위해 가능성이 있는 섭취·시술을 권고

식약처 식품 표시·광고 기준은 판매 또는 광고 맥락이 확인된 식품·건강기능식품 콘텐츠에만 대조한다. 검색 결과가 없다는 사실만으로 거짓이라고 판정하지 않는다.

## 5. 공장형 채널 가능성 — 채널별 0~100점

| 축 | 최대 점수 | 데이터 소스 | 계산 방법 |
|---|---:|---|---|
| 최근 생산량 | 25 | 업로드 재생목록 게시 시각 | 최근 30일 업로드 수를 고정 구간에 매핑 |
| 제목 템플릿 반복 | 25 | 최근 영상 제목 | 상투어 제거 후 정규화 문자열 유사도 계산 |
| 설명 본문 반복 | 15 | 최근 영상 설명 | 공통 안내문·링크 제거 후 본문 유사도 계산 |
| 주장 구조 반복 | 20 | 대표 영상의 검증된 건강 주장 | 분석한 3~5개 영상 안에서 동일 주장 서명 반복 비율 계산 |
| 채널 수명 대비 생산량 | 10 | 채널 개설일, 공개 영상 수 | 운영 기간 대비 월평균 생산량 계산 |
| 썸네일 템플릿 반복 | 5 | 썸네일 URL | 이미지 유사도와 OCR 문구 반복 분석 |

정확한 최근 30일 업로드 수는 업로드 재생목록을 기준일보다 오래된 영상이 나올 때까지 페이지 순회해 센다. 제목·설명·썸네일 반복성은 `최신 20개`와 `최근 30일 영상`의 합집합 중 최신 50개만 사용한다. 의미 기반 주장 반복성은 Gemini로 분석한 대표 영상 3~5개만 사용하며, 메타데이터 전체를 분석한 것처럼 표현하지 않는다.

초기 버전은 비교 집단이 필요한 백분위나 임베딩 모델을 사용하지 않고 다음 고정식을 쓴다.

```text
최근 생산량: 30일간 8/15/30개 이상이면 10/18/25점
제목 템플릿 반복: 25 × 반복 쌍 비율
설명 본문 반복: 15 × 반복 쌍 비율
주장 구조 반복: 20 × 반복 주장 서명 비율
채널 수명 대비 생산량: 활성 월당 12/30개 이상이면 5/10점
썸네일 템플릿 반복: 5 × 반복 쌍 비율
```

문자열은 Unicode 정규화, 소문자화, 숫자·날짜·상투어 치환 후 토큰 Jaccard 유사도 `0.8 이상`인 쌍을 반복으로 센다. 주장 서명은 `claimedOutcome + recommendedAction + certainty + subjectType`으로 만들며, 검증된 건강 영상이 3개 미만이면 주장 구조 반복 점수는 계산하지 않는다. 썸네일 분석을 구현하지 못했거나 데이터가 없으면 0점과 `미측정` 상태를 함께 표시한다. 모든 임계값과 정규화 상투어 목록은 규칙 버전에 포함한다.

채널 개설 연도만으로 점수를 주지 않는다. 신규 채널 여부는 짧은 운영 기간, 비정상적으로 많은 영상, 높은 제목·주장 반복도가 함께 나타날 때만 보조 신호로 사용한다.

## 6. 채널 콘텐츠 위험도

건강 관련 영상이 3개 미만이면 `근거 부족`으로 표시한다. 표본이 충분하면 다음과 같이 집계한다.

```text
채널 콘텐츠 위험도
= 건강 영상 중 위험도 상위 3개 평균 × 0.7
+ 동일 위험 주장 반복성 최대 20점
+ 권위 표방·판매 유도 반복성 최대 10점
```

- 내용 기반 위험 신호가 있는 영상이 최소 2개 있어야 고위험 채널이 될 수 있다.
- 대량 업로드와 제목 중복만으로 고위험 채널이 될 수 없다.
- 공장형 가능성은 별도 점수로 노출하고, 아래 등급 결정에서만 보조한다.

| 영상 콘텐츠 위험도 45~69 | 확인 필요 | 사용자가 선택한 영상에만 싫어요 |
| 영상 콘텐츠 위험도 45 미만 | 뚜렷한 신호 없음 | 채널 정보와 관계없이 액션 없음 |

위험한 채널에서 게시했다는 사실만으로 위험 신호가 없는 영상에 싫어요를 주지 않는다. 액션 정책 엔진은 제안과 기본 선택 여부만 결정한다. 실제 구독 취소와 싫어요는 사용자가 결과·근거·대상을 확인하고 최종 승인한 뒤에만 일괄 실행한다.

## 8. 사용자 흐름 A — 구독 목록

```text
YouTube Data API로 구독 목록 수집
→ 구독 채널의 공개정보와 업로드 목록 수집
→ 건강 관련 채널 선별
→ 결정적 규칙으로 대표 영상 선택
→ Gemini 영상 근거 수집과 OpenAI 주장 구조화
→ 추출 결과 검증 후 영상별 콘텐츠 위험도 계산
→ 채널 콘텐츠 위험도와 공장형 가능성 계산
→ 고위험 채널의 구독 취소를 기본 선택
→ 중간 위험 채널 선택 목록 제공
→ 결과와 근거 확인 후 사용자 최종 승인
→ 승인된 채널 구독 취소
→ 제안·선택 액션의 성공과 실패 결과 표시
```

## 9. 사용자 흐름 B — 최근 시청

```text
Data Portability API로 YouTube 활동 아카이브 요청
→ 완료된 아카이브에서 실제 시청 기록만 파싱
→ 건강 관련 영상을 선별하고 YouTube API로 상세정보 보강
→ 영상 채널의 최근 업로드 수집
→ 실제 시청 영상과 채널 대표 영상을 Gemini로 분석
→ OpenAI 주장 구조화와 근거 대조 후 콘텐츠 위험도 계산
→ 채널 콘텐츠 위험도와 공장형 가능성 계산
→ 고위험 영상의 싫어요를 기본 선택
→ 중간 위험 영상 선택 목록 제공
→ 결과와 근거 확인 후 사용자 최종 승인
→ 승인된 영상에 싫어요
→ 제안·선택 액션의 성공과 실패 결과 표시
```

최근 시청 기록은 분석 대상을 찾는 입력일 뿐, 시청 횟수·최근성·집중도는 위험 점수에 반영하지 않는다.

## 10. LLM 역할과 출력 계약

LLM은 점수를 직접 생성하지 않는다. Gemini는 공개 YouTube 영상에서 발언·화면 문구·타임스탬프를 근거 문서로 수집하고, OpenAI는 저장된 근거와 YouTube 메타데이터에서 도메인과 주장을 구조화한다. 서버는 구조화 결과를 동일한 근거 문서와 대조한 뒤 고정 규칙으로 점수를 계산한다.

```json
{
  "schemaVersion": "claim-v1",
  "isHealthContent": true,
  "claims": [
    {
      "evidence": {
        "sourceType": "video_segment",
        "videoId": "video-1",
        "evidenceSegmentId": "segment-3",
        "sourceSpan": "혈압약 끊고 이것만 드시면 됩니다"
      },
      "subject": "이것",
      "subjectType": "supplement",
      "condition": "고혈압",
      "claimedOutcome": "treatment",
      "recommendedAction": "stop_medication",
      "certainty": "guaranteed",
      "appliesUniversally": true,
      "context": "endorsed"
    }
  ],
  "evidenceReferences": [],
  "authorityClaims": [],
  "salesSignals": [],
  "persuasionSignals": []
}
```

검증 조건은 다음과 같다.

- Gemini 영상 근거는 영상당 한 번 생성해 모델·프롬프트 버전과 함께 저장하고 이후 단계에서 재사용한다.
- 각 추출 항목은 영상 세그먼트, 영상 제목, 영상 설명 또는 채널 설명을 구분하는 `EvidenceRef`를 가져야 한다.
- 영상 세그먼트 참조의 `evidenceSegmentId`는 저장된 Gemini 근거 문서에 실제로 존재해야 한다.
- `sourceSpan`은 `EvidenceRef`가 지정한 Gemini 세그먼트 또는 입력 메타데이터 원문에 정확히 존재해야 한다.
- 부정, 비판, 인용 맥락을 원 주장으로 오인하지 않아야 한다.
- 스키마 검증에 실패하거나 원문과 일치하지 않는 결과는 폐기한다.
- LLM은 허위 여부, 법 위반 여부, AI 생성 여부를 확정하지 않는다.
- 같은 구조화 결과에는 항상 같은 점수가 계산되어야 한다.
- Gemini 근거가 실제 영상과 완전히 일치하는지는 자동으로 확정하지 않으며, 타임스탬프 링크로 사람이 원본을 확인할 수 있게 한다.

## 11. 결과 화면

두 탭을 제공한다.

1. `구독 목록`: 채널 단위 결과와 구독 취소 액션
2. `최근 시청`: 시청 영상 단위 결과와 싫어요 액션

각 결과 카드에는 다음 정보를 표시한다.

- 채널명 또는 영상 제목
- 콘텐츠 위험도와 공장형 채널 가능성
- 핵심 판정 근거 1~3개와 원문
- 규칙 엔진의 기본 선택 또는 사용자 선택 여부
- 최종 승인과 API 실행 여부
- 실행한 액션과 성공·실패 상태
- 데이터가 보여주지 못하는 한계

결과 요약은 실행 후 `승인한 항목을 정리했어요`, `확인이 필요해요`, `그대로 두었어요`로 구분한다.

## 12. 현재 데이터와 분석으로 할 수 없는 판정

- 비공개·일부 공개 영상이나 Gemini가 처리하지 못한 영상의 본문 주장
- Gemini가 수집한 발언 근거와 실제 영상 사이의 완전한 자동 대조
- 영상 속 인물의 실제 의료 자격
- AI 생성 영상·음성 여부의 신뢰성 있는 확정
- 논문 인용의 정확성에 대한 완전한 검증
- 시청 지속시간, 완주 여부, 자동재생 여부
- YouTube 홈 추천 목록과 추천 진입 위치

데이터가 없으면 LLM의 배경지식으로 채우지 않는다. 결과는 `허위 채널`이 아니라 관측된 신호에 따른 `정리 우선순위`로 설명한다.

## 13. 데모 완료 조건

1. Google 계정 연결 후 구독 목록과 실제 최근 시청 기록을 별도 입력으로 가져온다.
2. 건강 관련 채널과 영상을 선별한다.
3. 콘텐츠 위험도와 공장형 채널 가능성을 분리해 계산하고 근거를 보여준다.
4. 고위험 채널의 구독 취소와 고위험 영상의 싫어요를 기본 선택한다.
5. 중간 위험 대상은 사용자가 직접 액션 후보로 선택한다.
6. 근거와 대상에 대한 최종 승인 뒤에만 YouTube 쓰기 API를 실행한다.
7. 기본 선택·사용자 선택 액션의 대상, 이유, 성공·실패 결과를 보여준다.
8. 테스트 계정과 공식 API만 사용하며 비밀정보를 저장소에 포함하지 않는다.
