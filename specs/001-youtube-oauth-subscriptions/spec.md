# Feature Specification: YouTube OAuth and Subscription Collection

**Feature Branch**: `feat/speckit-development`

**Created**: 2026-09-04

**Status**: Draft

**Input**: User description: "YouTube 계정을 안전하게 연결하고 전체 구독, 채널 정보와 업로드
메타데이터를 수집해 건강 관련 채널 후보를 준비한다. PRD의 FR-AUTH-*와 FR-COLLECT-*를 따른다."

## User Scenarios & Testing _(mandatory)_

### User Story 1 - Connect and Collect Every Subscription (Priority: P1)

사용자는 어떤 YouTube 데이터와 권한을 왜 사용하는지 확인한 후 Google 계정을 연결하고, 자신의
전체 구독 채널 목록이 누락 없이 수집되는 것을 확인한다.

**Why this priority**: 구독 목록은 이후 모든 분석과 사용자의 채널 정리 행동이 의존하는 유일한
입력이다. 안전한 연결과 완전한 수집이 없으면 다른 기능은 사용자 가치를 만들 수 없다.

**Independent Test**: 여러 페이지로 구성된 테스트 구독 계정을 연결해 수집을 시작하고, 원본 계정의
모든 구독이 하나씩 나타나며 각 항목에 채널 식별 정보와 구독 시각이 연결됐는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 연결되지 않은 사용자가 데이터 사용 목적과 구독 삭제 가능 권한 설명을 보고 있을 때,
   **When** 사용자가 Google 계정 연결을 선택하고 동의하면, **Then** 서비스는 해당 사용자만을 위한
   연결 세션을 만들고 구독 수집을 시작한다.
2. **Given** 사용자의 구독이 여러 응답 페이지에 나뉘어 있을 때, **When** 수집이 완료되면,
   **Then** 마지막 페이지까지의 모든 고유 구독이 누락과 중복 없이 포함된다.
3. **Given** 사용자가 Google 동의를 취소하거나 거부했을 때, **When** 서비스로 돌아오면,
   **Then** 수집은 시작되지 않고 계정 데이터가 저장되지 않으며 다시 시도할 수 있는 설명이 보인다.
4. **Given** 연결 응답이 현재 사용자의 연결 시도와 일치하지 않을 때, **When** 서비스가 응답을
   받으면, **Then** 연결을 거부하고 구독 데이터에 접근하지 않는다.
5. **Given** 데스크톱·태블릿·모바일에서 화면을 보는 시니어 사용자일 때, **When** 연결과 수집
   화면을 이용하면, **Then** 큰 글자와 조작 영역, 높은 대비, 아이콘과 텍스트가 함께 있는 상태
   표현으로 확대 없이 핵심 행동을 구분할 수 있다.

### User Story 2 - Prepare Channels for Health Analysis (Priority: P2)

사용자는 수집된 각 구독 채널에 대해 최신 채널 정보와 공개 업로드 메타데이터가 준비되고, 어떤
채널이 건강 관련 분석 후보로 분류됐는지 확인한다.

**Why this priority**: 전체 구독 ID만으로는 분석할 채널과 영상 표본을 정할 수 없다. 다음 점수 기능이
신뢰할 수 있는 입력을 받으려면 채널 보강, 공개 업로드 수집과 고감도 후보 분류가 필요하다.

**Independent Test**: 인증 단계는 준비된 연결 fixture로 대체하고, 정상·삭제·비공개·업로드 없음
채널을 함께 수집해 성공한 채널의 정보와 후보 상태, 실패한 채널의 이유가 각각 보존되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 수집된 구독 채널이 50개를 초과할 때, **When** 채널 정보 준비가 끝나면,
   **Then** 모든 고유 채널이 한 번씩 보강되거나 채널별 실패 이유를 가진다.
2. **Given** 공개 업로드가 있는 채널일 때, **When** 업로드 수집이 끝나면, **Then** 최근 90일
   업로드 패턴과 최신 20개를 판단할 수 있는 메타데이터가 준비된다.
3. **Given** 최근 90일에 500개보다 많은 업로드가 있는 채널일 때, **When** 안전 수집 상한에
   도달하면, **Then** 작업은 끝없이 계속되지 않고 수집이 잘렸다는 한계와 최소 확보 개수를 남긴다.
4. **Given** 채널 또는 일부 영상이 삭제·비공개·접근 불가 상태일 때, **When** 수집을 진행하면,
   **Then** 다른 채널의 수집은 계속되고 해당 항목만 제외 이유를 가진다.
5. **Given** 채널명·설명 또는 최신 영상 메타데이터에 건강 관련 신호가 있을 때, **When** 후보
   분류가 끝나면, **Then** 채널은 사용한 분류 정책 버전과 함께 건강 분석 후보로 표시된다.
6. **Given** 건강 관련 신호가 기준을 충족하지 않는 채널일 때, **When** 후보 분류가 끝나면,
   **Then** 점수를 추정하지 않고 비후보 상태만 기록한다.

### User Story 3 - Understand Progress and Partial Results (Priority: P3)

사용자는 오래 걸리는 수집이 어느 단계에 있는지 보고, 일부 외부 데이터가 실패해도 무엇이
완료됐고 무엇을 다시 시도해야 하는지 이해한다.

**Why this priority**: 채널별 업로드 수집은 구독 수에 따라 오래 걸리고 부분 실패할 수 있다. 진행과
한계를 숨기면 사용자는 멈춘 작업과 성공한 작업을 구분할 수 없다.

**Independent Test**: 지연과 일시 실패가 포함된 수집 fixture를 실행해 단계, 처리 개수와 최종
`완료`, `부분 완료`, `실패` 상태가 실제 결과와 일치하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 구독 수집이 진행 중일 때, **When** 사용자가 상태를 확인하면, **Then** 현재 단계와
   처리한 수, 전체 또는 현재까지 발견한 수가 표시된다.
2. **Given** 일부 채널만 수집에 실패했을 때, **When** 나머지 채널 처리가 끝나면, **Then** 작업은
   부분 완료로 표시되고 성공 수, 실패 수와 재시도 가능한 실패가 구분된다.
3. **Given** 인증이 만료되거나 철회됐을 때, **When** 다음 보호된 수집을 시도하면, **Then** 작업을
   계속하지 않고 재연결이 필요하다고 표시한다.
4. **Given** 서비스가 수집 도중 재시작됐을 때, **When** 사용자가 돌아오면, **Then** 중단된 작업을
   완료로 위장하지 않고 이어서 진행하거나 기존 작업을 폐기하고 새로 시작할 수 있게 한다.

### User Story 4 - Disconnect and Delete Collected Data (Priority: P4)

사용자는 언제든지 YouTube 연결을 해제하고 이 서비스가 저장한 자신의 구독·채널·업로드 수집
데이터를 즉시 삭제할 수 있다.

**Why this priority**: 민감한 계정 연결과 사용자별 구독 데이터는 사용자가 접근과 보관을 철회할 수
있어야 한다.

**Independent Test**: 수집 완료 fixture가 있는 연결 계정에서 연결 해제를 실행해 연결 상태가
사라지고 해당 사용자의 수집 작업과 데이터가 더 이상 조회되지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 연결된 사용자가 수집 데이터를 보유할 때, **When** 연결 해제를 확인하면,
   **Then** 외부 접근 권한의 철회를 요청하고 서비스에 저장된 해당 사용자 데이터와 세션을 삭제한다.
2. **Given** 외부 권한 철회 요청이 일시적으로 실패했을 때, **When** 내부 삭제가 끝나면,
   **Then** 사용자의 서비스 세션과 데이터는 복구되지 않으며 외부 계정 설정에서 직접 철회하는
   방법을 안내한다.
3. **Given** 이미 연결이 끊긴 사용자가 보호된 수집 결과에 접근할 때, **When** 요청하면,
   **Then** 이전 데이터가 노출되지 않고 새 연결을 요구한다.

### Edge Cases

- 구독이 0개인 계정은 오류가 아니라 빈 완료 결과를 반환한다.
- 같은 구독 또는 채널이 중복 응답되면 고유 ID 기준으로 하나만 유지하고 중복을 기록한다.
- 구독 목록의 채널명과 상세 채널명이 다르면 최신 상세값을 사용하되 원래 구독 관계는 유지한다.
- 채널 상세 응답에서 요청한 채널이 빠지면 해당 구독을 삭제하지 않고 `채널 정보 없음`으로 남긴다.
- 업로드가 없거나 모두 비공개인 채널은 후보 판단에 사용할 수 있는 정보가 부족함을 표시한다.
- 게시 시각이 없거나 잘못된 영상은 시간 기반 지표에서 제외하고 제외 수를 남긴다.
- 접근 제한이나 일시 오류가 한 채널에 발생해도 다른 채널 처리는 계속한다.
- 같은 사용자가 수집 버튼을 연속으로 눌러도 동시에 중복 작업을 만들지 않는다.
- 다른 사용자가 작업 ID를 알아도 해당 작업 상태나 결과에 접근할 수 없다.
- 보관 만료가 지난 작업은 결과 대신 만료와 새 수집 필요 상태를 반환한다.

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 서비스는 연결 전에 요청할 YouTube 데이터, 이용 목적, 구독 삭제 가능 권한과 연결
  해제 방법을 사용자가 이해할 수 있게 설명해야 한다. _(Source: FR-AUTH-002)_
- **FR-002**: 서비스는 사용자의 명시적 동의가 성공한 경우에만 계정 연결 세션을 만들어야 한다.
  _(Source: FR-AUTH-001)_
- **FR-003**: 서비스는 연결 응답이 현재 사용자가 시작한 일회성 연결 요청과 일치하는지 검증하고,
  불일치·만료·재사용 응답을 거부해야 한다. _(Source: FR-AUTH-003)_
- **FR-004**: 계정 접근 자격과 사용자별 구독 식별자는 해당 사용자 세션 밖으로 노출되거나 분석
  모델의 입력에 포함되어서는 안 된다. _(Source: FR-AUTH-004)_
- **FR-005**: 서비스는 연결된 사용자의 구독 목록을 끝까지 수집하고 고유 구독 관계를 누락과
  중복 없이 보존해야 한다. _(Source: FR-COLLECT-001, FR-COLLECT-002)_
- **FR-006**: 각 구독은 구독 관계 ID, 구독 시각, 채널 ID, 표시 이름, 설명과 사용 가능한
  썸네일을 가져야 한다. _(Source: FR-COLLECT-002)_
- **FR-007**: 서비스는 고유 채널별 최신 상세정보와 공개 업로드 목록 식별자를 준비해야 한다.
  _(Source: FR-COLLECT-003)_
- **FR-008**: 채널이 없거나 접근할 수 없어도 전체 수집을 중단하지 않고 해당 구독에 실패 이유를
  연결해야 한다. _(Source: FR-COLLECT-004)_
- **FR-009**: 서비스는 각 접근 가능한 채널에서 최근 90일 업로드 패턴과 최신 20개 공개 영상
  메타데이터를 판단할 수 있을 만큼 업로드 목록을 수집해야 한다. _(Source: FR-COLLECT-005)_
- **FR-010**: 채널별 업로드 수집은 500개에서 중단하고, 상한 도달 시 수집이 잘렸음을 표시해야 한다.
- **FR-011**: 비공개·삭제·식별 불가 업로드는 분석 입력에서 제외하고 채널별 제외 이유와 개수를
  보존해야 한다. _(Source: FR-COLLECT-006)_
- **FR-012**: 서비스는 채널명·설명과 최신 영상 제목·설명만으로 고감도 건강 후보 분류를 수행하고
  판정과 정책 버전을 저장해야 한다. _(Source: FR-COLLECT-007)_
- **FR-013**: 후보 분류는 건강 관련 가능성을 놓치지 않는 것을 우선하며, 최종 콘텐츠 리스크나
  공장형 가능성을 생성해서는 안 된다.
- **FR-014**: 수집 작업은 현재 단계, 발견·처리·성공·실패·제외 개수와 최근 갱신 시각을 제공해야 한다.
- **FR-015**: 일부 채널 실패 시 성공 데이터를 보존하고 작업을 부분 완료로 구분해야 한다.
- **FR-016**: 인증 만료·철회는 채널 실패와 구분하고 남은 보호 데이터 접근을 중단해야 한다.
- **FR-017**: 동일 사용자의 활성 수집 작업은 하나만 허용하고 중복 시작 요청에는 기존 작업을
  반환해야 한다.
- **FR-018**: 모든 작업과 결과는 소유 사용자만 접근할 수 있어야 한다.
- **FR-019**: 분석 준비 데이터는 수집 완료 또는 실패 후 24시간이 지나면 조회할 수 없어야 한다.
- **FR-020**: 사용자는 계정 연결 해제를 요청할 수 있고, 서비스는 외부 접근 철회를 시도한 뒤
  세션과 저장된 사용자별 데이터를 즉시 삭제해야 한다. _(Source: FR-AUTH-005)_
- **FR-021**: 인증이 만료되거나 철회된 경우 서비스는 데이터를 추측하거나 작업을 계속하지 않고
  재연결 필요 상태를 제공해야 한다. _(Source: FR-AUTH-006)_
- **FR-022**: 이 기능은 인기 영상 선정, 영상 콘텐츠 judge, 두 점수 계산, 결과 채널 선택과 구독
  해제 실행을 수행해서는 안 된다.
- **FR-023**: 중단된 작업이 있으면 사용자는 마지막 체크포인트에서 재개하거나 해당 작업을 폐기하고
  새 작업을 만들 수 있어야 하며, 두 행동 모두 동시에 두 작업을 실행해서는 안 된다.
- **FR-024**: 사용자 화면은 `design-brief.md`의 연두색 작업 바·밝은 회색 패널·대형 기능 타일을
  반응형으로 적용하되, 제3자 로고·마스코트·제품 이미지를 복제해서는 안 된다.
- **FR-025**: 기본 본문은 18px 이상, 주요 버튼·입력의 최소 조작 영역은 52×52px 이상이어야 하며,
  상태는 색상만이 아니라 텍스트와 아이콘으로 함께 전달해야 한다.

### Key Entities

- **Connected Account**: 사용자가 동의해 연결한 YouTube 계정의 현재 연결 상태와 권한 만료 상태.
  접근 자격 증명 자체는 사용자에게 노출되지 않는다.
- **Connection Attempt**: 사용자가 시작한 일회성 연결 요청. 요청자, 만료와 사용 여부를 가진다.
- **Collection Job**: 한 사용자의 구독·채널·업로드 수집 실행. 단계, 상태, 처리 개수, 실패와
  보관 만료를 가진다.
- **Subscription**: 사용자와 구독 채널 사이의 관계. 구독 관계 ID, 시각과 채널 연결을 가진다.
- **Channel Profile**: 구독 채널의 최신 공개 설명 정보와 업로드 목록 연결 상태.
- **Upload Metadata Sample**: 채널의 공개 업로드 패턴과 최신 콘텐츠를 판단하기 위해 확보한
  영상 식별자, 제목·설명과 게시 시각의 제한된 표본.
- **Health Candidate Classification**: 채널이 다음 영상 분석 단계에 들어갈 후보인지 나타내는 판정,
  사용한 정책 버전과 판정에 사용 가능한 표본 상태.
- **Collection Failure**: 특정 단계·채널·영상에서 발생한 격리된 실패. 재시도 가능 여부와 사용자용
  이유를 가진다.

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 테스트 참가자의 90% 이상이 별도 도움 없이 2분 안에 권한 설명을 확인하고 계정
  연결 또는 취소를 완료한다.
- **SC-002**: 0개, 1개, 51개와 500개 구독 fixture 각각에서 원본 고유 구독의 100%가 누락 없이
  수집되고 중복 결과는 0건이다.
- **SC-003**: 정상 조건의 200개 구독 계정에서 사용자는 수집 시작 후 1초 안에 진행 상태를 보고,
  작업 중에는 5초 이내 간격으로 갱신된 진행 정보를 확인한다.
- **SC-004**: 채널의 10%가 접근 불가인 fixture에서 접근 가능한 채널의 100%가 준비되고, 실패
  채널의 100%가 원인과 함께 부분 완료 결과에 나타난다.
- **SC-005**: 건강 후보 기준 fixture에서 확정된 건강 채널의 recall이 95% 이상이고, 어떤 후보도
  콘텐츠 리스크나 공장형 점수를 포함하지 않는다.
- **SC-006**: 연결 해제 후 해당 사용자의 세션, 구독, 채널, 업로드와 작업 데이터 조회 성공 건수가
  0건이며 보호된 화면은 새 연결을 요구한다.
- **SC-007**: 연결 실패, 인증 만료, 채널 부분 실패, 수집 상한과 데이터 만료의 각 fixture에서
  사용자가 확인 가능한 상태와 다음 행동이 100% 제공된다.
- **SC-008**: 브라우저 응답, 사용자에게 보이는 URL, 클라이언트 로그와 분석 모델 입력에서 계정
  접근 자격, 비밀키와 구독 관계 ID의 노출 건수가 0건이다.
- **SC-009**: 360px 모바일 폭, 768px 태블릿 폭, 1280px 데스크톱 폭과 200% 브라우저 확대에서
  가로 스크롤 없이 연결·수집·연결 해제 핵심 흐름을 키보드로 완료하고, 주요 조작 영역의
  100%가 52×52px 이상이다.

## Assumptions

- v1은 자신의 계정을 연결하는 한 명의 사용자 역할만 지원하며 타인 계정 대리 관리는 제외한다.
- 개발과 워크숍에서는 프로젝트에 허용된 테스트 계정만 사용한다.
- 사용자는 연결과 수집 중 안정적인 인터넷 연결을 사용할 수 있다.
- 구독 조회와 향후 명시적 구독 삭제에 필요한 권한을 최초 연결에서 함께 설명하고 요청한다.
- refresh token을 장기 보관하지 않으며 접근 권한이 만료되면 사용자가 다시 연결한다.
- 건강 후보 분류는 다음 단계의 비용을 줄이는 고감도 필터다. 최종 건강 관련성과 콘텐츠 위험을
  확정하지 않는다.
- 모든 수집 데이터와 작업 결과의 기본 보관 기간은 완료 또는 실패 후 24시간이다.
- YouTube API 데이터로 자체 파생 지표를 공개 제공하는 기능은 별도 컴플라이언스 게이트를 통과한
  뒤 활성화한다.
